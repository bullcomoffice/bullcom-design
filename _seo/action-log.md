## A-1 URL正規化が無い（https / 非www / 末尾スラッシュ）🔴未着手

- **検出**: 2026-08-30 初回外形チェック。外形3項目が同時に落ちている
  - `http://bullcom.website/` → **HTTP 200**（301していない）
  - `https://www.bullcom.website/` → **HTTP 200**（301していない）
  - `/blog/{id}/` → **HTTP 307**（301ではない）
- **なぜ問題か**: 同じページが `http` / `https` / `www` / 末尾スラッシュ有無 の**最大8通りのURL**で
  200を返す。Googleは一時リダイレクト(307)では評価を統合しないため、
  被リンクとクロール予算が分散し、GSCに「重複・正規未選択」が積み上がる。
  canonical は入っているが、301のほうが確実。
  姉妹サイト bullcom.jp で同じ状態を検出したばかり（あちらの A-1 / A-2）
- **対策案**: `worker.js` の `handler.fetch` の先頭で正規化する。
  現状は `/api/contact-submit` 以外を素通しで `env.ASSETS.fetch(request)` に渡しているため、
  アセット層が 307 を返す前に Worker 側で 301 を返せる。
  https・非www・末尾スラッシュ無しの3条件をまとめて評価し、差分があるときだけ301を1回返す
  （bullcom.jp の `src/worker.js` が同じ作りなので流用できる）
- **注意**: このサイトの正規形は**末尾スラッシュ無し**。bullcom.net は逆なので実装をコピーしないこと
- **結果**: —

## A-3 robots.txt が Cloudflare Managed で、AIクローラをブロックしている 🔴未着手

- **検出**: 2026-08-30 初回外形チェック。自前の `robots.txt` が無く、
  **Cloudflare の Managed robots.txt** が配信されている。内容は
  `GPTBot` / `ClaudeBot` / `Google-Extended` / `CCBot` / `Bytespider` / `Amazonbot` /
  `Applebot-Extended` / `meta-externalagent` を **`Disallow: /`**
- **なぜ問題か**: **GEO（AI検索での露出）を目的にしているのに、AIクローラを名指しで拒否している**。
  ChatGPT・Claude の学習/参照経路と Google の AI Overviews 向けクロールが塞がっており、
  この状態でGEO引用テストをしても出ないのが当然。運用の前提が崩れる。
  あわせて `Sitemap:` 行も無い（A-2とセット）
- **なお**: `OAI-SearchBot` と `PerplexityBot` は個別指定が無いため `User-agent: *` の
  `Allow: /` にフォールバックしており、現状も許可されている
- **対策案**: ①Cloudflareダッシュボードで Managed robots.txt を無効化 →
  ②`app/robots.ts`（または `public/robots.txt`）で自前配信。AIクローラ許可 + `Sitemap:` 行を入れる。
  bullcom.jp / bullcom.net と同じ方針に揃える
- **判断が要る点**: 「AIに学習させたくない」という意図でCloudflare側を有効にしたのであれば、
  GEO運用そのものの方針を先に決める必要がある。**着手前にユーザー確認**
- **結果**: —

## A-5 ブログ記事に Article 構造化データが無い 🔴未着手

- **検出**: 2026-08-30 初回外形チェック。`/blog/{id}` に `BreadcrumbList` はあるが
  **`Article` が未検出**
- **なぜ問題か**: 記事の著者・公開日・見出し画像がGoogleに伝わらず、
  検索結果のリッチな見え方（発行日表示など）が出にくい。パンくずだけ入っている中途半端な状態
- **対策案**: `app/blog/[slug]/page.tsx` に `Article`（headline / datePublished / dateModified /
  image / author / publisher）のJSON-LDを追加する。bullcom.jp の実装を流用できる
- **結果**: —

## A-6 記事の meta description がタイトルと同一 🔴未着手

- **検出**: 2026-08-30 初回外形チェック。`app/blog/[slug]/page.tsx:26` が
  `description: blog.title` になっており、**description がタイトルと一字一句同じ**（40字）
- **なぜ問題か**: 検索結果のスニペットがタイトルの繰り返しになり、クリックの動機を与えられない。
  bullcom.jp で同じ状態を修正したばかり（あちらの A-4）
- **対策案**: 本文（`blog.content`）からHTMLタグを除いて先頭100〜120字を抜粋する
  ヘルパーを追加する（bullcom.jp の `lib/excerpt.ts` を流用）。
  microCMSのリッチテキストなので、タグ除去とエンティティのデコードが要る
- **効果検証**: 表示回数の多い記事のCTRが動くかを**月次**で確認する
- **結果**: —

## A-7 GA4 が未設置 🔴未着手

- **検出**: 2026-08-30 運用新設時。`app/layout.tsx:125` に
  「GA4 の測定ID発行後、bullcom 本家と同様に `<Script>` で gtag を設置する」のTODOが残っている
- **なぜ問題か**: **週報のデータ収集3項目（セッション / 直帰率 / 新規記事PV）と、
  月報のコンバージョン（フォーム送信数）が永久に埋まらない**。
  GSCだけでは「検索で見られた」までしか分からず、サイト内の行動が測れない
- **対策案**: GA4プロパティを作成 → 測定IDを共有 → `app/layout.tsx` に設置。
  フォーム送信は `/contact?sent=1` の到達をコンバージョンに設定する
  （送信後に同一オリジンへ302で戻る作りなので、ページビューで拾える）
- **依存**: ユーザー作業（プロパティ作成）が先
- **結果**: —
