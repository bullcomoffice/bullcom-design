# 月次レビュー（bullcom.website）— GSC / GA4 / マップ / AI検索

**毎月最終日曜 13:00・1時間**（カレンダー予定 `FREQ=MONTHLY;BYDAY=-1SU`）。
その週の週次レポートは実施せず、本レビューが兼ねる。
自動起動はしない — 「BULLCOM designの月次レビューやって」と指示して始める。
タイミングと手順の定義は
[`report-operation.md`](../../bullcom/_seo/report-operation.md)。

対象期間は前回月報の翌日〜実施日前日（週次ログ4〜5週分）。
暦月の数字が要る項目は GSC の「過去28日」も併記する。

## 0. 週次分の引き継ぎ（月報が週報を兼ねるため必須）

省くとその週の答え合わせが抜け落ちる。

1. 外形チェック（`npm run seo:log`）— [`health-log.md`](./health-log.md) の直近と比較し退行を指摘
2. **答え合わせ** — [`action-log.md`](./action-log.md) の 🔵検証中 / ⏳継続観察 のステータス更新
3. 当週データの取得と [`weekly-log.md`](./weekly-log.md) への記録

## 1. 月次レビュー本体

1. **週次データ4〜5週分の推移をグラフ化**（表示回数/クリック/CTR/平均順位 — weekly-log.md から集計）
2. **主軸キーワードの平均掲載順位推移**（最新の定義は [`README.md`](./README.md) の「対象キーワード」）
   > 個別KWの精査はここ（月次）が担当。週次では追わない。
   > あわせて毎月、**選定時に存在しなかった新規クエリの台頭**を確認し、必要なら主軸KWを入れ替える
3. **コンバージョン**: お問い合わせフォーム送信数（GA4）
   > GA4未設置のうちは、Resend の送信ログ or 受信メール件数で代替する
4. **GEO引用率の変化**: 週次のGEO引用テスト○×の月間集計
5. **リライト候補選定**: GSCで表示回数多×順位低の記事
6. **翌月の記事テーマ 3〜5本決定**
   > microCMS に毎週水9:45の予約公開で積んである。既存の予約分と重複しないこと

## 2. GSC の健全性確認

プロパティ: `sc-domain:bullcom.website`

1. **検索パフォーマンス**（過去28日）— 合計クリック/表示/CTR/平均順位。伸びた・落ちたクエリをメモ
2. **ページのインデックス登録** — 「登録済み」数の推移。「重複・正規未選択」が減っているか
   > 2026-08-30 にURL正規化（A-1）を入れたので、http/www/末尾スラッシュ違いの重複は
   > 以降で減っていくはず。減っていなければ正規化が効いているか外形チェックで確認する
3. **URL検査（トップ）** `https://bullcom.website` が登録されているか
4. **サイトマップ** — `https://bullcom.website/sitemap.xml` が「成功しました」か / 検出URL数
5. **拡張（構造化データ）** — FAQ / パンくず / 記事 のレポートにエラーが出ていないか
6. **インデックス登録リクエスト**（必要時・ユーザー承認後）

## 5. GEO（AI検索での露出）

- ChatGPT / Claude / Perplexity で「神戸 ホームページ制作 おすすめ」
  「ホームページ制作 丸投げ できる」「LP制作 安い 神戸」等を質問し、
  bullcom.website が引用/言及されるか。されれば引用箇所をメモ
- 姉妹サイト bullcom.jp（パソコン修理）・bullcom.net（セキュリティ）と競合しない、
  **design の担当領域を名指しした質問**も必ず入れる（「デザイン」「LP」「ブランディング」「サイト保守」等）
- AIクローラの許可は 2026-08-30 に解消済み（A-3）。ただし引用に反映されるまで時間がかかるので、
  数週間は○×の記録を積むだけにして傾向判断は急がない。
  **Cloudflare側の設定（ゾーン概要ページ右カラム「AI ボットアクセスを管理」）が
  許可のままかも毎回見る**。戻されると引用が止まる（外形チェックにも項目あり）
