# ブログ記事の作成ルール（bullcom.website）

既存27本（2026-07-01〜12-30 公開分）の実測と投入スクリプトの仕様から整理した規約。
新しい記事を書くときはこのルールに従う。

## 1. ファイルと配置

- このフォルダに `NN-slug.md`（例: `28-keitai-hyoji.md`）で置く。**NNは公開順（order）とゼロ埋めで揃える**
- 1ファイル = 1記事。フロントマター＋本文＋SNS投稿文をこの1ファイルで完結させる

```markdown
---
order: 28              ← 公開順。毎週水曜9:45に order 順で1本ずつ公開される
no: 28                 ← 制作通し番号（原稿管理用）
category: デザイン      ← 4分類のいずれか（下記）
title: 記事タイトル
---

（本文）

---

## SNS投稿

（SNS投稿文）
```

## 3. 本文のルール

### 構成・分量（既存27本の実測レンジ）

- **本文 600〜970字**（中央値 690字）。長文にしない — 1テーマ1記事で薄く広くより深く狭く
- **h2見出し（`## `）を4〜5個**。h3以下は使わない
- タイトルは **21〜41字**（中央値29字）。読者の疑問・不安をそのまま言葉にする形
  （例:「あとからページを追加できる？」「『丸投げ』でも大丈夫？」）

### ⚠️ 使える記法は「## 見出し」と「段落」だけ

`build-posts.py` の変換器は **h2 と p しか出力しない**。太字・箇条書き・リンク・画像・
引用は**変換されずそのまま文字列になる**ので使わないこと。リストにしたい内容は
「1つ目は〜。2つ目は〜。」と文章で書く。

### 書き出し（冒頭段落）が meta description になる

`lib/excerpt.ts` が**本文の先頭110字**を検索結果のスニペットに使う。
冒頭の1〜2文で「誰のどんな悩みの話か」が伝わるように書く。
あいさつ・時候・自己紹介から始めない。

### 文体

- です・ます調。**制作者本人が相談に答えている一人称**（「〜することがあります」「〜をおすすめします」）
- 専門用語は出したらすぐ言い換える（例:「静的サイト＝あらかじめ完成品のページを置いておく方式」）
- 売り込まない。読者の判断材料を渡して、最後に一度だけ誘導する
- 他社・他手法を貶さない（WordPress記事でも「向き不向き」の書き方に留める）

### 締めのCTA（全記事必須）

最終セクションで自然に相談へ誘導する。**全27本共通で以下の要素を含む**:

- ご相談・お見積りは無料であること
- 電話番号 **078-912-2656**
- お問い合わせフォームへの言及

例: 「ご相談・お見積りは無料ですので、お電話（078-912-2656）またはお問い合わせフォームからどうぞ。」

### 事実情報

料金・サービス内容・営業時間などは**要件定義書 §8 と `lib/site-data.tsx` が正**。
記事内で金額を書くときは必ず照合する（LP3万円〜 / HP20万円〜 / 保守 月5,000円〜 等・税別）。

## 4. SNS投稿文（`## SNS投稿` セクション・必須）

IG / FB / GBP の自動投稿に使われる。無いと既定文「【新着記事】{タイトル}」になってしまう。

- **本文2〜4行・35〜40字/行程度**。絵文字を1〜3個（🤔✨👇など）。ひらがな多めの柔らかい文体
- 記事の要点を「よくある相談 → 気づき」の形で
- 末尾は **「詳しくはこちら👇」**（リンクはスクリプトが自動付与）
- **ハッシュタグはちょうど5個**・半角スペース区切り。
  `#ホームページ制作` `#中小企業` ＋ 記事テーマのタグ3つ が基本形

## 5. サムネイル（アイキャッチ）

1. **gpt-image-2 で背景画像を生成**（APIキーは `D:\Data\Projects\Next\bullcom\.env.local` の
   `OPENAI_API_KEY`。手順は同リポジトリ `.claude/commands/blog-create.md` STEP3）
   - トーン: 明るい白基調・自然光・パステル＋ビビッド（ピンク/紫/青/シアン/オレンジ）・
     **人物なし・文字なし**・フォトリアル → `thumbs/thumb-NN.jpg`
2. `compose-thumbs.py` の `TITLES` に**短縮タイトル（2行・各10字前後）**を追加して実行
   → バッジ＋短縮タイトル＋ロゴを合成した **1280x720** が `thumbs-final/` に出る
3. microCMS のメディアにアップして記事の eyecatch に紐付け
4. **`public/blog-thumbnails/{記事ID}.jpg` にもコミットする（必須）**。
   Instagram投稿はこのURLを使う（microCMSのeyecatchは0バイト事故の実績があるため使わない）

## 6. 投入手順（microCMS）

```bash
# 1) SNS連投防止のキルスイッチを先に入れる（必須）
gh secret set SNS_POST_MAX_MINUTES --body 0

# 2) 原稿→JSON変換（media-urls.json にアイキャッチURLを追記してから）
python build-posts.py     # → posts.json

# 3) 投入（下書き作成→予約設定）。連投レート制限があるので2秒スリープ入り
./post-all.sh

# 4) SNS投稿文の再生成（記事IDをキーにした辞書。忘れると既定文になる）
#    scripts/sns-post-texts.json に新記事分を追加

# 5) サムネを public/blog-thumbnails/{記事ID}.jpg にコミット → push

# 6) キルスイッチ解除
gh secret set SNS_POST_MAX_MINUTES --body 60
```

### 公開スケジュール

- **毎週水曜 9:45（JST）に1本**。APIへは UTC（`T00:45:00.000Z`）で渡す
- 予約は2段階: `POST /blogs?status=draft` → `PUT .../contents/blogs/{id}/reservation`
- 公開済みに予約は付けられない（先にDRAFTへ戻す）。状態変更は `PATCH .../status` に**配列**で
- 既存の予約と**日付が重複しないよう**、最後の予約日（現在: 12/30まで埋まっている）の翌週から積む

### ⚠️ 事故防止

- APIキーに「**下書きコンテンツの全取得**」を付けない（未公開記事がサイトとSNSに漏れる）
- `publishedAt` の変更・一括公開時も先にキルスイッチ（Webhookは日付の巻き戻しでも飛ぶ）
- 予約公開が走ると **Webhook → デプロイ＋SNS投稿（IG/FB/GBP）まで全自動**。
  つまり「予約を入れる＝その日に投稿されると確定」の意識で

## 7. 公開後の確認

- `/blog` に記事が出ているか・カテゴリバッジの色が付いているか
- meta description が冒頭文になっているか（タイトルの繰り返しになっていないか）
- SNS3媒体の投稿（画像・カスタム文・リンクが `https://bullcom.website/blog/{id}`）
- 週次レポート（日曜13:00）で索引状況を追う

- **月次レビュー（最終日曜）で翌月の3〜5本を決める**のが正規ルート
